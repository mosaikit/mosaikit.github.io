Build applications out of plugins

Mosaikit is a multi-tenant web platform. The kernel gives every application what it needs: tenants, users, roles, permissions, public links, KPIs. Plugins add the rest, one domain at a time, like the tiles of a mosaic.

Why Mosaikit

Plugins carry the domain

The kernel knows nothing about notes, maps or documents. Each plugin brings its own logic, interface and data. The official plugins cover documents, notes, tasks, contacts, maps, sites, layouts and a language.

Safe by construction

Plugin logic runs as WebAssembly in a sandbox; its interface is isolated in an iframe with its own origin and content security policy.

Multi-tenant from day one

Three roles (Administrator, Tenant Manager, User), sharing with people and groups, public links and a quota for every tenant, in the core.

PostgreSQL or SQLite

The same isolation rules hold on PostgreSQL (row-level security) and on SQLite (query rewriting, triggers and an authorizer), so one product runs on a server or on a desktop.

Runs where you need it

A Windows desktop release, a Docker image with Compose files and a Kubernetes release, built with one command each.

Make your own product

A product is a separate project on the compiled platform: its brand, its choice of plugins, its own plugins and its defaults. The dev kit covers it.

Try it

The repositories are public. With Rust, Node.js and PostgreSQL (or only SQLite) installed:

git clone https://github.com/mosaikit/mosaikit
git clone https://github.com/mosaikit/mosaikit-plugins
cd mosaikit
cargo xtask dev

To write a plugin or a product without the platform source, use the dev kit: the mosaikit-plugin tool, the SDK, the UI API and the documents.
