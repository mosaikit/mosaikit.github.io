Build applications out of plugins

Mosaikit gives you the foundations every application needs: sign-in, users, organizations, languages, themes. Plugins add the rest, screens, services and data, piece by piece, like the tiles of a mosaic.

Why Mosaikit

Plugins all the way down

A plugin can extend the core and other plugins, so a feature can be extended without being forked.

Any frontend framework

Plugin interfaces are Web Components: each team picks the framework it prefers.

Multi-tenant from day one

Organizations, users, local sign-in and federation with external identity providers are in the core, with row-level security on the data.

Runs where you need it

A container image and a Helm chart for Kubernetes, and a portable distribution for a single machine, also offline.

Open, and open to business

The core is licensed under MPL-2.0: build open-source or commercial plugins on top of it.

Verifiable

Signed plugin packages and catalogs, a software bill of materials and signed checksums with every release.

Build a plugin

Generate a plugin with its manifest, its app and, with --backend, Java code and a database schema. It builds against the plugin API published on Maven Central and npm.

npx @mosaikit/create-plugin dev.acme.traffic --name "Traffic" --backend

See the plugin development guide.
